# POOL — Hidden-gems research (discovery-first)

> Run on 30 Sep 2026 by 8 discovery researchers with no tool names supplied up front, using at least 4 discovery channels each and checking every find live. A skeptical critic spot-checked the 10 most important gems and compared all 123 against our current picks.
> Generated from `research/raw/hidden_gems.json`. Nothing was retyped by hand.

## 1. Critic verdict

### Swaps (replace a current pick)

- **Temporal (pool timers, payout holds) plus pg-boss and Valkey/BullMQ for jobs → DBOS Transact TS (@dbos-inc/dbos-sdk, MIT), pinned to 5.2.x, running in-process on the same Postgres. It ships a Drizzle template. Do not use DBOS Conductor SaaS; self-host it or skip it for India data. Keep Valkey only if a cache is later needed.** (medium)
  - Why: Spot-checked on GitHub and npm: MIT, 1,380 stars, v5.0 on 2026-09-16, v5.1 on 09-24, v5.2 on 09-29, npm 5.2.11. It gives durable sleep until the buyer-chosen close, checkpointed steps (capture, then Route transfer on_hold, then Wave Drop refunds), recv/timeouts for the delivery-code wait, rate-limited queues for WhatsApp sends, and exactly-once cron. That removes three moving parts (Temporal cluster or cloud, Redis, a queue library) for 5 Windows developers, and it survives a crash without double refunds.
  - Risk: Three minor releases in two weeks, so pin exactly and read changelogs before upgrading. DBOS closed its 'PGLite support' issue as not_planned (2026-03-11) and uses LISTEN plus its own connections, so it will NOT run on PGlite. Local dev needs real Postgres (Docker or a per-developer cloud branch). Workflow code must be deterministic, with every side effect in a step. The community is smaller than Temporal's.
- **US pools longer than about 7 days: charge in full via Stripe Connect, then a Wave Drop partial refund at close → Stripe manual capture with payment_method_options.card.request_extended_authorization=if_available. Capture only the winning per-buyer price with amount_to_capture. Read charge.payment_method_details.card.capture_before to cap each buyer's closing-time picker.** (high)
  - Why: Verified on Stripe's docs today. Mastercard allows 30 days in all categories. Visa allows 29d 18h in all categories, with a +0.08% fee outside lodging and rental. Test cards 4242 and 5555 exercise it in test mode, and the docs say availability in test mirrors live. Networks intend it for cases where the final amount is unknown at authorisation, which is POOL's case. The buyer is never charged and then refunded, so there are fewer disputes and no refund float.
  - Risk: Needs IC+ pricing, or a support request on blended pricing, before live use. Amex and Discover get extended windows only in travel and lodging, so those cards fall back to a 7-day cap or charge-and-refund. Not available when Link is the payment method type. Holds must use clear statement descriptors. Keep the charge-and-refund path as a fallback.
- **Meilisearch (separate search service plus sync pipeline) → Postgres-native search for the prototype: tsvector with the 'simple' configuration, pg_trgm for fuzzy and Telugu/Hindi script, and pgvector (Voyage) similarity, fused with reciprocal rank fusion in one SQL query. Consider pg_textsearch BM25 only if the chosen host supports it.** (medium)
  - Why: For a prototype catalogue of thousands of products and pools, a second stateful service and a sync pipeline cost more than they return. Everything already lives in Postgres 18 with pgvector. pg_textsearch is real (PostgreSQL licence, v1.4.0 on 2026-08-18) but only runs on Tiger Cloud or self-hosted, so it is not a safe default.
  - Risk: Relevance tuning and typo tolerance are weaker than Meilisearch's out of the box. Telugu/Hindi quality with 'simple' plus trigram must be tested on real queries. Re-add Meilisearch if search becomes a product surface.
- **Socket.IO for live pool updates → Server-Sent Events through oRPC event iterators, fed by Postgres LISTEN/NOTIFY or DBOS events** (medium)
  - Why: POOL's live data only flows one way: joins count, countdown, price tier and 'new bid arrived'. SSE runs over plain HTTP, reconnects automatically, passes proxies and CDNs, and needs no sticky sessions or Redis adapter. That is lighter on low-end Android and on ops. oRPC was verified: MIT, @orpc/server 1.15.4 stable on 2026-09-23.
  - Risk: Buyer-to-buyer chat or seller two-way interaction would need WebSockets later. Some serverless hosts cap long-lived responses, so run SSE from the long-running Node service. Do not use oRPC v2 beta.

### Additions

- **pgledger (vendored pgledger.sql inside Drizzle migrations)** — _prototype_: A real double-entry ledger that commits in the same Postgres transaction as order and pool state. Verified in the source: allow_negative_balance and allow_positive_balance checks, plus accounts locked in sorted order with FOR UPDATE to avoid deadlocks. MIT, 494 stars, pushed 2026-09-30. Add POOL's own idempotency-key table, because pgledger has none. Its README roadmap admits there are no numbered upgrade migrations yet, so pin the SQL file.
- **Dinero.js v2 (2.0.2 stable)** — _prototype_: Typed INR/USD money with allocate(), so Wave Drop rebates and commission splits sum exactly to the paise or cent. It gives compile-time errors on currency mismatch. Verified on npm: 2.0.2, MIT.
- **fast-check 4** — _prototype_: Property tests: refunds + seller payout + fee = captured amount, and no buyer ever pays more than the accepted guaranteed price. The same properties cover the pool state machine. This is the evidence of money correctness investors and auditors want.
- **UPI Reserve Pay (SBMD), behind a feature flag** — _prototype_: For India pools under Rs 10,000: block the maximum price at join, then debit only the final price at close. Verified: Razorpay caps it at Rs 10,000 and 90 days, requires activation via support and an eligible business category, supports only BHIM/INDmoney/Navi/Paytm, and mentions no test mode. Cashfree documents a sandbox (sandbox.cashfree.com/pg/subscriptions). Neither says whether the debit can carry Route transfers or split settlement. Build it only after the PA confirms sandbox access and split/hold compatibility in writing. Keep charge plus Wave Drop refund as the default path, because PhonePe and GPay users (most of India) cannot use it yet.
- **Claude web_fetch_20260318 + strict tool use / structured outputs, with an 'evidence quote' pattern** — _prototype_: Verified: web fetch is GA, costs nothing beyond tokens, and supports allowed_domains, max_uses, max_content_tokens and use_cache. Two corrections to the gem. (1) Citations and structured outputs are INCOMPATIBLE: the citations doc says the API returns 400 if both are used, so the proposed messages.parse + citations design fails. Instead, make every schema field carry a verbatim evidence_quote, and verify server-side that the quote appears in the fetched page text. Any unverified field is shown as 'unconfirmed'. (2) Web fetch does not run JavaScript and refuses robots.txt-blocked URLs. Keep cheerio+metascraper (JSON-LD/OG, often including GTIN and price) as the first deterministic step, with Playwright/Firecrawl as the fallback.
- **zxing-wasm / barcode-detector polyfill** — _prototype_: Deterministic GTIN from the pack barcode, so no AI guess is needed. Also QR display and scanning of the delivery/pickup code in the PWA, including iOS Safari. MIT. Lazy-load the ~1 MB WASM.
- **Voyage voyage-multimodal-3.5 (inside the existing Voyage pick)** — _prototype_: Embeds image plus title, so a Flipkart link and an Amazon.in link for the same product land in one pool. Claude then makes the final same/different call through a strict tool.
- **Sarvam Saaras v4 (codemix + keyterms) and Bulbul v3** — _prototype_: Telugu/Hindi WhatsApp voice notes turned into pool actions, with Telugu voice replies. The REST limit is 30 s per clip, so use batch for longer notes. Run a word-error-rate test on 30 real Hyderabad voice notes first.
- **Borzo Business API v1.8 sandbox** — _prototype_: Verified: sandbox URL robotapitest-in.borzodelivery.com, up to 99 points per order, is_route_optimizer_enabled, place_photo_url and sign_photo_url proof per drop, order and delivery webhooks, and Hyderabad listed. One pickup plus N buyer drops per pool, with real proof on the tracking timeline. Adds a public, self-serve sandbox next to the Delhivery/Shiprocket picks.
- **DIGIPIN (port the official India Post encoder into a TS package)** — _prototype_: An offline, deterministic ~4 m address code on every pickup and drop, used in WhatsApp messages and courier notes. The GitHub API shows NOASSERTION, so confirm the LICENSE file says Apache-2.0 before copying.
- **Takumi (OG images + PDF receipts)** — _prototype_: A live WhatsApp share card per pool (joined count, current price, closes-at) plus receipts, with no Chromium. Verified: 3,057 stars, 2.14.0, Apache/MIT. It has no Indic issues filed, but also no Telugu proof. Render a Telugu and Devanagari test card on day 1; if conjuncts break, fall back to next/og or a Playwright screenshot.
- **NumberFlow (@number-flow/react)** — _prototype_: Rolling-digit price drops with Intl en-IN grouping, which is the emotional core of the pool page. Web only.
- **oRPC 1.15.x contract package** — _prototype_: One Zod contract gives the typed web client, generated OpenAPI for dealer integrations and the MCP server, and SSE streams. Mount it in the long-running Node service next to the DBOS workers.
- **Hookdeck CLI** — _prototype_: A permanent webhook URL per developer for Razorpay, Cashfree and Meta test events, with replay for debugging hold and refund edge cases. Test data only, because events pass through Hookdeck's cloud.
- **PGlite (for Vitest only)** — _prototype_: A throwaway real Postgres per test file for pure SQL, pgledger and pricing tests with no Docker. Not the dev database, because DBOS does not support it.
- **TypeScript 7.0.2 + Oxlint 1.x type-aware + Oxfmt (pinned)** — _prototype_: Much faster type checks and linting on 5 Windows laptops, and no-floating-promises on webhook and refund code. Correction: Next.js 16.3 docs say the tsc CLI checker is ON by default, so no flag is needed. Tools that call the TS JS API need the @typescript/typescript6 alias until TS 7.1.
- **pnpm 12 (minimumReleaseAge 1440, blockExoticSubdeps, trustPolicy no-downgrade) + Socket Firewall Free + Betterleaks + zizmor + Knip** — _prototype_: A cheap supply-chain and secret hygiene layer for laptops that hold Razorpay, Stripe, Meta and Anthropic keys. sfw is PolyForm Shield with mandatory telemetry, which is acceptable for a dev tool.
- **Playwright Test Agents (planner/generator/healer) + vitest-evals** — _prototype_: Golden-flow E2E written by agents and kept in the repo. Also a 100-link product-identification eval that fails CI if accuracy drops or a field lacks verified evidence.
- **Serwist + Declarative Web Push (Safari 18.4+)** — _prototype_: An offline shell for the PWA opened from WhatsApp links, and working iOS web push for US buyers before any native app exists.
- **Grafana k6 v2 (internal only; AGPL is fine for a tool that is never shipped)** — _prototype_: A load test of the last-60-seconds join burst and refund fan-out before any live investor demo.
- **Varlock** — _prototype_: Typed .env.schema, boot-time validation and log redaction across roughly 25 India/US keys, so a missing key fails at startup instead of mid-pitch.
- **WhatsApp Flows + Flowso emulator** — _prototype_: 'Join pool' and 'submit sealed bid' forms inside WhatsApp for sellers who will not install an app. Flowso (MIT, weeks old) is only a local dev emulator. Meta's own Cloud API test number is used for real sends.
- **Stripe Tax stays; c15t for US web consent** — _prototype_: GPC/CCPA-aware consent gating for PostHog replay on the US web app. India DPDP notices remain custom work, because c15t maps India to NONE.
- **Cashfree Secure ID Name Match + Attestr FSSAI check** — _prototype_: A 'Verified seller' badge backed by dated GSTIN, penny-drop name match and FSSAI licence checks for meat shops. Use forward penny drop only: reverse penny drop is not permitted for e-commerce MCCs.
- **WhatsApp Payments API (order_details, Razorpay deep integration)** — _after_prototype_: In-chat 'pay your final price'. Verified: deep integration supports only Razorpay, PayU, Billdesk and Zaakpay, with refunds only in deep mode. The Meta page does not mention Route/transfers, so get written confirmation from Razorpay before wiring it into the held-split flow. It also needs an approved WABA.
- **Expo-side kit: hot-updater, expo-share-intent, Legend List v3, react-native-keyboard-controller, TrueSheet, Reanimated 4 CSS, Pulsar haptics, Anek + Noto Telugu fonts** — _after_prototype_: A premium, low-end-Android-friendly native app once the Expo phase starts. Fonts (OFL) can also be used on the web immediately.
- **Marble + ThumbmarkJS** — _after_prototype_: Rules and a case manager for Wave Drop inflation, bait bidding and duplicate-device buyers. ELv2 is fine for internal use.
- **GrowthBook (Postgres-native experiments), PostHog Workflows, Dub deep links** — _after_prototype_: Experiments measured on paid-and-handed-over orders, lifecycle nudges and install attribution, once real users exist.
- **Bugsink in ap-south-1 (Sentry SDK compatible)** — _after_prototype_: India-resident error data with no SDK changes. Its licence is PolyForm Shield (source-available).
- **Claude Code GitHub Action** — _prototype_: PR review against POOL money and DPDP invariants, with no per-seat SaaS. Use a cheaper model for routine reviews.

### Rejected gems

- **Vite+ 1.0 (vp)**: Real (MIT, 1.0.0 on 2026-09-28) but two days old. Its docs do not cover a Next.js/Turbopack app, and the Windows setup exe is unsigned. Too risky as the build backbone of an investor prototype. Use plain pnpm workspaces now and revisit in Q1.
- **json-render (Vercel Labs)**: Pre-1.0 Labs project. The guarantee it offers is already provided by strict tool schemas plus POOL's own fixed Zod-typed React components and server-side evidence checks. It adds churn without adding safety.
- **Zero / Electric + TanStack DB / PowerSync**: Each adds a stateful sync service and logical replication, and a permission mistake could leak sealed bids. SSE covers the prototype's one-way live data.
- **Absurd, Vercel Workflow DevKit, PgQue, Microsoft pg_durable**: Pick exactly one durable engine (DBOS). These are pre-1.0, in major-version beta, or need extensions most hosts lack.
- **pg_textsearch as the Meilisearch replacement**: Real and active, but it only runs on Tiger Cloud or self-hosted Postgres, not RDS, Supabase or PlanetScale. Use pg_trgm + tsvector + pgvector instead.
- **Hyperswitch Prism**: Pre-1.0, with no split, hold or payout abstraction. POOL's hard parts are exactly Route and Connect.
- **Kintsugi**: Its tax API is paywalled on Premium and it adds nothing to a prototype. Stripe Tax covers demo-time calculation.
- **Kapso as BSP**: Meta's Cloud API already provides a free test business number for development. Kapso is a small LatAm-focused startup with no India pricing, so there is no clear gain over going direct.
- **WhatsApp Groups API**: Verified cap of 8 participants and it needs an Official Business Account (green tick). It cannot hold a real pool.
- **textbee (phone as SMS gateway)**: Sending commercial SMS from a personal SIM is not TRAI DLT-compliant. It would undermine the 'real, no shortcuts' pitch. Use MSG91 with DLT.
- **LinkForty Core**: AGPL core, 41 stars, Expo SDK with 0 stars. Too immature; Dub is the attribution option later.
- **Libredesk**: AGPL, and its WhatsApp channel is only in a release candidate with no calling. Chatwoot already covers this.
- **OfferKit, @marinedotsh/better-auth-referral, notifkit**: Very early (v0.1-0.3, low activity). The referral plugin does not support phone-OTP signup. A referral table plus pgledger credits is small enough to build.
- **Didit (for India) / Aadhaar UIDAI lookup**: Aadhaar-based checks carry UIDAI legal constraints and Indian PII residency is unverified. Cashfree DigiLocker/PAN flows already cover this. Consider it only for US seller KYC later.
- **Sandbox.co.in as a replacement for Cashfree Secure ID**: Pricing is not public, and it has no clear gain over a pick that is already integrated. Keep it as a fallback for GST return-filing checks.
- **Flue, UCP, Infisical Agent Vault, Claude Managed Agents**: Young or beta, and not on the buyer critical path. UCP and agent payments stay a roadmap slide, as the project state file already decided.
- **mcp-use (as a replacement for the official MCP SDK)**: Fast-moving, with breaking changes between majors. The official SDK + mcp-handler already works; switch only if MCP Apps widgets become a must-have.
- **Laminar (replacing Langfuse)**: No clear gain. Langfuse remains MIT and self-hostable.
- **Lynx 4.0, Rive Nitro runtime, RCS India, UIDAI OVSE, ONDC Beckn-ONIX, Cashfree OneEscrow, TesterArmy, Blacksmith, HeroUI Native, React Bits, Google Stitch**: Watch only. Each is either pre-1.0, needs approvals or legal setup, overlaps existing picks, carries a non-OSI licence (React Bits uses Commons Clause), or does not affect the prototype.

### Top 10 investor "wow" moments (all real, no fake data)

1. Paste a real Flipkart or Amazon link: Claude returns the exact product, and every field is shown with the verbatim quote from the source page (verified server-side). Anything it cannot prove is labelled 'unconfirmed' on screen.
2. Scan the barcode on a real pack with zxing-wasm and get a GTIN-exact match. Two buyers pasting different store links for the same item land in the same pool (Voyage multimodal plus a Claude same/different check).
3. Hold, don't charge (US): a Stripe test-mode extended authorisation shows as a hold. At close only the lower winning price is captured and the rest releases, visible live in the Stripe dashboard.
4. A live pool page where the price rolls down with NumberFlow as real joins arrive over SSE, plus a WhatsApp share card (Takumi) that shows the current price and time left, regenerated on every join.
5. A Telugu voice note on WhatsApp ('rendu kilo mutton curry cut, Sunday') is transcribed by Sarvam Saaras v4 and turned into a pool join by Claude, with a Telugu voice reply from Bulbul v3.
6. A seller submits a private bid through a WhatsApp Flow without installing an app. The buyer sees the guaranteed per-buyer price and accepts or walks away.
7. Proof-based delivery: one Borzo sandbox multi-drop order per pool with route optimisation, per-drop photo and signature proof, a DIGIPIN on every address, and a scan of the buyer's QR handover code that releases the Razorpay Route on_hold transfer.
8. Crash-proof money, shown live: kill the worker process in the middle of a pool close. DBOS resumes from the last checkpoint, and the pgledger trial balance still ties to the paise with Razorpay/Stripe test-mode records, with no double refunds.
9. A 'Verified seller' badge built from real, dated checks: GSTIN, then penny-drop bank name match against the GST legal name, then FSSAI licence validity for meat shops.
10. Join a pool from inside Claude through POOL's own MCP server (find_pool, join_pool, pool_status). Payment still completes on POOL's licensed-PA checkout, never inside the chat.
